Openhouse

a proxy you run yourself

Open the web,
on your own terms.

Openhouse fetches pages on its own connection and hands them to you — so a site blocked by a school, office, or café network still opens, as long as this server itself can reach it.

How a page gets through

  1. 01

    You ask this server

    Your browser only ever talks to Openhouse — never directly to the blocked site.

  2. 02

    It fetches the page

    Openhouse requests the site over its own network connection, wherever it's hosted.

  3. 03

    It hands it back, rewritten

    Links and assets are rewritten to keep routing through the proxy as you click around.

Worth knowing

Best for reading

News, wikis, docs, blogs, and forums come through cleanly. Heavy single-page apps (Gmail-style dashboards, most social feeds) often don't.

Logins are shaky

Simple username/password forms usually work. Google, Facebook, and other single-sign-on logins generally don't — they actively resist proxies.

Video is hit or miss

Streaming sites like YouTube rely on tricks this proxy doesn't reproduce, so playback is unreliable.

It's only as open as its server

If the network hosting Openhouse itself blocks a site, the proxy can't reach it either.

Openhouse runs on a server you control. Nothing you browse is sent anywhere but that server.
